# CodeGraph — граф символов проекта

Локальный индекс кода: SQLite + FTS5 в `.codegraph/codegraph.db` в корне проекта, без сети и ключей. Отдаёт символы, а не строки: где объявлен, кто вызывает, что сломается.

Пакет `@colbymchenry/codegraph`, глобально через npm. Проверенная версия — 1.6.2.

## Установка на новой машине

```bash
npm install -g @colbymchenry/codegraph@1.6.2
codegraph install -t claude -l global -y
```

Второй шаг делает всё из следующего раздела. Порядок и остальные инструменты — `rules/machine-bootstrap/machine-bootstrap.md`.

## Что уже настроено глобально

Сделано один раз командой `codegraph install -t claude -l global -y`:

| Где | Что |
| --- | --- |
| `~/.claude.json` | MCP-сервер `codegraph` — `codegraph serve --mcp`, stdio |
| `~/.claude/settings.json` | `permissions.allow: mcp__codegraph__*` |
| `~/.claude/settings.json` | хук `UserPromptSubmit` → `codegraph.cmd prompt-hook` |
| `~/.claude/CLAUDE.md` | указатель на правило (маркерный блок плагина снят вручную) |
| `~/.codegraph/telemetry.json` | телеметрия выключена |


## Команды

Все принимают `-p <path>`; без него работают от текущего каталога, поэтому запускать из корня
проекта.

| Команда | Когда |
| --- | --- |
| `codegraph explore "<вопрос или имена символов>"` | **Первый заход всегда сюда.** Исходники нужных символов + пути вызовов между ними, одним ответом. Заменяет серию Grep → Read |
| `codegraph node <symbol\|file>` | Один символ или файл целиком с номерами строк + кто от него зависит |
| `codegraph query <search>` | Поиск символа по имени, когда неизвестно точное написание |
| `codegraph callers <symbol>` | Кто вызывает. Находит вызовы через интерфейс и базовый класс, которые Grep по имени пропускает |
| `codegraph callees <symbol>` | Кого вызывает |
| `codegraph impact <symbol>` | Радиус поражения перед изменением сигнатуры или удалением |
| `codegraph affected <files...>` | Какие тесты задеты правкой |
| `codegraph files` | Структура проекта по индексу |
| `codegraph status [-j]` | Статистика и pending-изменения. Чем проверяется свежесть графа |
| `codegraph sync` | Инкрементальное обновление |
| `codegraph index` | Полная переиндексация с нуля |
| `codegraph init` | Первичная инициализация проекта |
| `codegraph uninit` | Снести `.codegraph/` из проекта |

MCP-инструмент `codegraph_explore` = CLI `explore`. У агентов со списком `tools` MCP-инструмента может не быть — тогда CLI через Bash; в процедурах агентов прописан CLI.

## Unity: `codegraph.json` кладётся ДО первого `init`

Без него `explore` вернёт исходники UPM-пакетов вместо проекта. Файл в корне, рядом с `Assets/`:

```json
{
  "exclude": [
    "Library/",
    "Temp/",
    "Obj/",
    "obj/",
    "Logs/",
    "UserSettings/",
    "Build/",
    "Builds/",
    "MemoryCaptures/",
    "Recordings/",
    "**/*.csproj",
    "**/*.sln",
    "**/*.unitypackage"
  ],
  "deprioritize": [
    "Assets/Plugins/",
    "Assets/ThirdParty/",
    "Assets/Editor Default Resources/",
    "Assets/**/Demos/",
    "Assets/**/Examples/"
  ]
}
```

Почему именно так:

- `Library/PackageCache` — тысячи `.cs` из UPM, главный источник распухания базы и мусорных ответов.
- `.csproj`/`.sln` Unity перегенерирует при каждом импорте: без исключения вотчер дёргает ресинк впустую.
- `Temp/`, `Obj/`, `Logs/`, `UserSettings/` — мусор сборки и локальные настройки.
- `Assets/Plugins` и `ThirdParty` задепориоритетены, не исключены: чужой код иногда нужен, но не должен всплывать выше своего.

Дополнительно:

- `.codegraph/` — в `.gitignore` проекта (локальная база).
- Без git `.gitignore` не действует, исключения держатся только на `codegraph.json` — класть его первым.
- `init` на крупном Unity-проекте — минуты CPU и сотни МБ на диск; молча в чужом проекте не запускать.

## Когда звать `sync`

Авто-синк включён: файловые вотчеры с дебаунсом ~2 с. После каждой правки `sync` не нужен.

Звать обязательно:

- после массового создания, переименования или удаления скриптов — сгенерировал пачку файлов,
  перенёс папку, вырезал механику;
- после `git pull`, смены ветки, отката, применения патча;
- когда `codegraph status` показывает pending-изменения или ошибку;
- когда ответ `explore` не бьётся с тем, что видно в файле, — а если и после `sync` не бьётся,
  то `codegraph index`.

Не нужно:

- после правки тела одного метода;
- после правки сцен, префабов, ассетов, `manifest.json` — граф про них ничего не знает.

## Чего граф не умеет

Это код-граф, не модель Unity-проекта:

| Не видит | Чем смотреть |
| --- | --- |
| Сцены и префабы, связи `[SerializeField]`, `UnityEvent` из инспектора | Unity MCP |
| Значения в ScriptableObject-ассетах | Read, Unity MCP |
| Ссылки по GUID в `.meta` и `.asset` | Grep по GUID |
| Загрузку по строковым путям — Resources, Addressables, `SendMessage`, рефлексия | Grep по строке |
| Пакеты и версии в `Packages/manifest.json` | Read |

По C# заявлено полное покрытие символов (классы, интерфейсы, структуры, енумы, методы); процент
cross-file resolution из их бенчмарка (85.2%) относился к версии 1.6.0 и устарел. Это значит: **пустой ответ графа не
доказывает, что вызовов нет.** Перед удалением символа или сменой сигнатуры `impact` — первый
шаг, но не единственный: контрольный Grep по имени обязателен.

## Fallback

Переходить на Grep/Glob и сказать об этом владельцу, если:

- в корне проекта нет `.codegraph/` — индексацию владелец решает сам, молча не индексировать;
- `codegraph status` ругается, а `sync` и `index` не помогли;
- `explore` вернул пусто на символ, который точно существует;
- команда `codegraph` не найдена — плагин не установлен или сломался после обновления.

Граф — ускоритель, не источник правды: расходящийся с файлом ответ молча за полный не выдавать.

## Обновление

`codegraph upgrade` внутри вызывает `install --refresh` и **может вернуть маркерный блок
`<!-- CODEGRAPH_START -->` в `~/.claude/CLAUDE.md`**. После обновления проверить конец файла и снести блок: указатель на правило там уже есть.

После `codegraph upgrade` в каждом проекте с `.codegraph/` — `codegraph index`: исправления разрешения ссылок (релиз 1.6.2) записываются при индексации, старая база их не содержит.
