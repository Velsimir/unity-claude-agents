# Математика idle / incremental игр

Жанровая глубина к `ECONOMY.md` (§2.1 экспонента, §2.3 prestige). Общий каркас — источники,
стоки, время до покупки — там; здесь формулы покупки пачками, цепочки генераторов и варианты
prestige.

Источник (пересказ формул, не копия): Kongregate, «The Math of Idle Games», части
[I](https://www.kongregate.com/en/pages/the-math-of-idle-games-part-i),
[II](https://www.kongregate.com/en/pages/the-math-of-idle-games-part-ii),
[III](https://www.kongregate.com/en/pages/the-math-of-idle-games-part-iii).

Формулы считать в `TEMPLATES/simulate.py` или таблице, не в уме.

## 1. Генератор: цена и выработка

Обозначения: `b` — базовая цена, `r` — рост цены, `k` — сколько уже куплено, `n` — сколько
покупаем, `c` — валюта на руках.

```
cost_next  = b * r^k
production = prod_base * owned * multipliers
```

Пример (AdCap, Lemonade Stand): `r = 1.07`, `b = 4`, `prod_base = 1.67/с`. При 10 штуках:
`cost_next = 4 * 1.07^10 = 7.87`, `production = 16.7/с`.

### Покупка пачкой

Стоимость `n` штук подряд (сумма геометрической прогрессии):

```
cost(n) = b * r^k * (r^n - 1) / (r - 1)
```

Сколько штук можно купить на `c`:

```
max = floor( log_r( c * (r - 1) / (b * r^k) + 1 ) )
    = floor( ln( c * (r - 1) / (b * r^k) + 1 ) / ln(r) )
```

Вторая запись — для языков без логарифма по произвольному основанию.

Граница применимости: обе формулы верны только для чистой экспоненты. Скачки цены на вехах,
скидки, сдвиг показателя ломают их — тогда считать циклом.

### Баланс

- Экспонента цены рано или поздно обгоняет любой степенной рост выработки, при любых `k` и `n`.
  Баланс управляет только тем, **когда** произойдёт перегон.
- Множители-вехи (×2 на 25 и 50 штук в AdCap) складываются и дают всплески покупок. Позиции вех —
  главный рычаг ритма.
- Prestige умножает выработку: игрок успевает уйти дальше по кривой цены, прежде чем отстанет.
- Выбор между генераторами считается по отношению доход / цена на момент покупки. Модель «за
  секунду» завышает медленные дорогие тиры, потому что не учитывает таймеры завершения — игрок
  дешёвый тир «не чувствует», а модель его не выберет.

## 2. Цепочка генераторов (производные)

Тир 1 производит валюту, тир `i+1` производит тир `i`. Одна штука верхнего тира, при выработке
1/с на каждом уровне, даёт валюту по закону:

| Тиров в цепочке | Валюта от времени `x` |
| --- | --- |
| 1 | `x` |
| 2 | `x^2 / 2` |
| 3 | `x^3 / 6` |
| n | `x^n / n!` |

Количество штук к моменту `t` (3 тира): `1 + t + t^2/2 + t^3/6` — усечённый ряд `e^x`.
Конечная цепочка растёт полиномом `n`-й степени, а не настоящей экспонентой.

Следствие: цена на экспоненте, выработка на полиноме — разрыв растёт всегда. Это и есть
замедление жанра; ширину и крутизну задают число тиров и `r`.

Поколение внутри секунды: штука, появившаяся в текущую секунду, даёт в ней половину выработки
(`t=2: 0.5 + 1 + 0.5 = 2`). Учитывать при дискретной симуляции по тикам.

### Приёмы из Derivative Clicker

- **Цена по купленному, не по имеющемуся.** Штуки, полученные от верхнего тира, цену не двигают.
  Пример: тир 1 стоит `5 * 1.1^n`, где `n` — число *купленных*.
- **Бонус за покупку.** Каждая купленная штука тира даёт всем штукам этого тира +0.05%. Ручные
  покупки остаются значимыми даже при миллиардах штук от автоматики.
- **Расширения.** Несколько валют; генератор, питающий несколько валют или генераторов; перекрёстная
  зависимость выработок. Каждое усложнение — повод пересчитать модель, а не править формулу.

## 3. Prestige: варианты формул

Обозначения: `p` — всего prestige-валюты, `Δp` — прирост за сброс, `c_L` — заработано за всё
время, `c_M` — максимум валюты за один забег, `c_R` — заработано за этот забег.

| Игра | Формула | База | Удвоить `p` — сколько надо заработать |
| --- | --- | --- | --- |
| Realm Grinder | `p = (sqrt(1 + 8*c_M/1e12) - 1) / 2` | максимум за забег | ≈ 4× от прошлого максимума |
| AdVenture Capitalist | `p = 150 * sqrt(c_L / 1e15)` | за всё время | ≈ 3–4× |
| Cookie Clicker | `p = cbrt(c_L / 1e12)` | за всё время | ≈ 8× |
| Egg, Inc. | `Δp = (c_R / 1e6)^0.14` (≈ 1/7) | только этот забег | ≈ 2^7 = 128× |
| Clicker Heroes | от числа купленных апгрейдов героев | этот забег | логарифмоподобно |

Realm Grinder выведена из `c_M = 1e12 * p(p+1)/2` решением квадратного уравнения
`p^2 + p - 2*c_M/1e12 = 0`. Сброс на том же максимуме новой prestige-валюты не даёт.

### Что выбирать

- **За всё время** (AdCap, Cookie): повторный сброс на той же точке всё равно платит, но с
  убывающей отдачей — игрок вынужден двигаться дальше. Показатель корня задаёт, во сколько раз
  нужно больше заработать на удвоение.
- **За забег** (Egg, Clicker Heroes): результат не зависит от прошлых забегов, рост плоский и
  догоняется системами «за всё время». У Clicker Heroes цена апгрейдов экспоненциальна, поэтому
  валюта растёт как логарифм — это позволяет сбросом пройти стену сложности на той же отметке.
- **Максимум за забег** (Realm Grinder): сброс без продвижения не платит вовсе.
- Показатель степени — рычаг темпа. Корень (1/2) — быстрые повторы, 1/3 — реже, 1/7 — каждый
  забег должен быть заметно длиннее.

### Ограничители и темп

- Egg, Inc.: вложенный prestige-цикл даёт около ×5 за круг; оффлайн ограничен 2 часами, чтобы
  прогресс шёл через активную игру.
- Забеги должны чередовать быстрые и медленные участки — за счёт множителей и апгрейдов на вехах.
  В таблице с одним генератором вехи 300/400/500 штук давали всплески покупок, а ×16 на 500
  штуках закончил долгий участок, начатый на 120-й минуте.
- Проверка по `ECONOMY.md` §2.3: следующий забег на той же дистанции быстрее в 2–5 раз.

### Как проверять

Таблица в первом приближении даёт ощущение динамики, но не поведение игрока. Баланс требует
нескольких итераций; начать с таблицы, потом перенести в `TEMPLATES/simulate.py` с персонами.
Сначала определить, в чём главное удовольствие игры — новые фичи, достижения или оптимизация
prestige — и крутить числа вокруг этого.
