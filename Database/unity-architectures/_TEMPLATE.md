# Профиль архитектуры: <название>

> Шаблон. Копировать в `Database/unity-architectures/<ARCH-NAME>.md`. Профиль заводится, когда
> архитектура пришла в работу, а не впрок. По реальному проекту, без имён донора — только имена
> фреймворка и роли.

## Признаки

По чему разведка (`unity-architecture-recon`) узнаёт архитектуру. Каждый признак проверяется
поиском, а не впечатлением:

| Признак | Где смотреть | Вес |
|---|---|---|
| пакет `<id>` | `Packages/manifest.json` | решающий / поддерживающий |
| тип или атрибут `<Name>` | код | решающий / поддерживающий |
| объект или компонент | сцена, префаб | поддерживающий |

Минимум для уверенного вывода: какие признаки обязаны совпасть. С чем легко спутать и как отличить.

## Адаптация кода из библиотеки

Код в `MECHANICS/*/TEMPLATES/` написан под Zenject-фундамент. Что меняется при переносе:
базовые классы, регистрация, реактивщина, сейв. Что остаётся как есть (обычно — ядро правила).
