# Стиль кода C#

Источник истины по стилю для кода агента `unity-foundation` и скилла `unity-mechanic-library`.
Применяется ко всем `.cs` файлам проекта.

## Структура файла и класса

- **Namespace повторяет путь от папки** под `Assets/`. Корень — **имя проекта**, а не `_Project` (например, `MyGame.Core.Services.Save`). Имя папки на диске любое: корень namespace задаётся один раз при генерации фундамента и не меняется.
- **Порядок членов класса**: Поля → Конструктор → Свойства → Методы.
- **Внутри каждого блока** — по модификатору доступа: `public` → `protected` → `private`.
- **События** относятся к полям (выше всех остальных полей).
- **Модификаторы доступа — всегда явно**, кроме членов интерфейса (там подразумевается `public`).

## Именование

- `camelCase` — локальные переменные, параметры (`canMerge`, `playerMoney`).
- `_camelCase` — `private` поля (`_coins`, `_animator`).
- `PascalCase` — `public` и `protected` поля (protected как public, без подчёркивания), **свойства** (всегда), методы, классы, интерфейсы, структуры, enum, namespace.
- `UPPER_SNAKE_CASE` — `const` (любой модификатор доступа). **Переопределяет** общий принцип «константы PascalCase».
- `static readonly` и `readonly` поля — **не константы**, именуются по правилу полей (`PascalCase` для public, `_camelCase` для private).
- **Bool-методы**: `IsX` / `CanX` / `HasX` (`IsEmpty()`, `CanMerge()`). Не `CheckX` — размыто, туда прокрадываются side-effects.
- **`bool TryX(...)`** — методы, которые могут не выполниться и возвращают флаг успеха (`TryBuild`).
- **Свойства-флаги** — так же: `IsEmpty`, `CanMerge`.
- **События** — в прошедшем времени (`Killed`, `Damaged`); хендлеры — `OnX` (`OnKilled`), иногда допустимо без `On`.
- **Существительные** — классы, поля, свойства; **глаголы** — методы.
- **Точные имена, без сокращений.**
- **Множественное число для коллекций** (`coins` — список, `coin` — одна).
- **Без тавтологии**: `Character.Move()`, не `Character.CharacterMove()`.
- **Без размытых имён** (`GameManagerController`, `…Manager`, `…Helper`) — имя отражает ответственность.

## Форматирование

- **`[SerializeField] private`** — для инспектор-полей (см. `WalkingView._animator`).
- **Явные типы вместо `var`** — `foreach (GameEntity timer in _timers...)`, не `foreach (var timer in ...)`.
- **Не более одной пустой строки подряд.**
- **Блоки `if` / `switch` / `for` / `while` отделяем пустой строкой** от соседнего кода.
- **Проверка на `false`**: `if (x == false)`, **не** `if (!x)` — `!` легко не заметить.
- **Между `case` в `switch` — пустая строка.**
- **Группируем код пустыми строками** между методами и логическими блоками.

## Содержимое

- **Никаких магических чисел** — в именованную `const` или поле. Допустим `0`, если смысл однозначен (проверка на пустоту коллекции).
- **Без вычислений в выводимом тексте** (`Debug.Log`, интерполяция строк) — выводим готовый результат.
- **Убирать дубляж**: повторяющиеся блоки → в метод.

## Комментарии

- **Комментариев в коде нет.** Ни `//`, ни блочных, ни `///`-XML над классами и методами.
  Смысл несут имена, типы и структура.
- Исключение одно: **неочевидное «почему»**, которое код выразить не может — обход бага
  платформы, константа из внешней спецификации, требование к порядку вызовов. Не «что делает
  метод», а «почему так, хотя напрашивается иначе».
- Нужно объяснение — в ответ пользователю или в базу знаний, а не в файл.

## Особенности компилятора Unity

Код компилируется в голове, но не в редакторе:

- **`record` и `init` требуют полифилла.** Unity собирает под netstandard2.1, где нет
  `System.Runtime.CompilerServices.IsExternalInit`, а компилятору C# 9 он нужен. Без файла
  с пустым `internal static class IsExternalInit` в namespace `System.Runtime.CompilerServices`
  любой позиционный `record` падает с `CS0518: Predefined type ... is not defined or imported`.
  В фундаменте файл лежит в `Core/Common/IsExternalInit.cs`.
- **В `MonoBehaviour` нельзя занимать имена магических методов.** Свойство или поле `Update`,
  `FixedUpdate`, `LateUpdate`, `Start`, `Awake`, `OnDestroy` даёт `CS0102: the type
  already contains a definition`. Если интерфейс требует такое имя — реализуй явно
  (`Observable<float> ITickService.Update => _update;`): конфликта нет, потребители не замечают.
  Так сделан `TickService`.
- **`Object` неоднозначен** при `using System` вместе с `using UnityEngine` — `CS0104`.
  Лечится алиасом `using Object = UnityEngine.Object;` в начале файла, а не полным именем
  в каждой строке.

## Асинхронные методы

- **Тип возврата — `UniTask` / `UniTask<T>` / `UniTaskVoid`.** `Task` / `Task<T>` не используем. Корутины не используем вообще.
- **Суффикс `Async` обязателен** для любого метода, возвращающего `UniTask` / `UniTask<T>` / `UniTaskVoid`: `StartAsync`, `LoadAsync`, `UnloadAsync`, `WarmupAssetsByLabelAsync`. И публичные, и приватные, и сигнатуры в интерфейсах.
- **`UniTaskVoid` — только для fire-and-forget**, когда `await` невозможен (точка входа из `Start()` MonoBehaviour-а — см. `GameplayBootstrap.CustomSetup`). Имя — тоже с `Async`.
- **`async void` запрещён.** Единственное исключение — обработчик C#-event / UnityEvent, чья сигнатура требует `void`; тогда тело **обязано** быть в `try`/`catch`, иначе исключение проглотится без следа.
- **`CancellationToken` — последним параметром**, имя `cancellationToken`, после необязательных параметров со значениями по умолчанию. Пробрасывай токен во все вложенные `*Async`-вызовы.
