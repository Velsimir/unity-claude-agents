# Система сохранений

Три требования, из которых выведена схема:

1. Всё грузится **один раз на старте**, до появления геймплея.
2. Пишем **в важных точках**, а не на каждое изменение.
3. Облако трогаем **минимально** — иначе лимиты сгорают за день.

## 1. Состав

```
ISaveService       фасад для игры: MarkDirty(reason), ForceSaveAsync(), LoadAsync()
ISaveParticipant   контракт секции: Key, Order, Capture(), Restore(data)
SaveRegistry       список участников, инжектится Zenject'ом автоматически
SaveScheduler      политика записи: dirty-флаг, троттлинг, флаш
ISaveStorage       куда пишем: LocalFileSaveStorage, CloudSaveStorage
```

Бога-координатора, перечисляющего подсистемы руками, **не делаем**. Сервис, который хочет
сохраняться, реализует `ISaveParticipant`:

```csharp
public interface ISaveParticipant
{
    string Key { get; }   // имя секции в файле, стабильное навсегда
    int Order { get; }    // порядок восстановления, см. ниже
    object Capture();
    void Restore(object data);
}
```

Zenject отдаёт все реализации списком, регистр не знает ни одного конкретного типа.
**Добавление системы = правка одного файла.**

**`Order`** — порядок восстановления бывает значим: ставка дохода и флаг «реклама отключена»
применяются раньше, чем считаются офлайн-награды.

### Системные секции и порядок

| Key | Order | Участник | Что хранит |
|---|---|---|---|
| `clock` | 0 | `GameClock` | максимальное виденное UTC (защита от отката часов) |
| `dayRollover` | 1 | `DayRolloverService` | последние виденные сутки |
| `timers` | 5 | `TimerService` | `Id` + `EndUtcTicks` активных таймеров |

Механики берут `Order` от 10 и выше. Часы восстанавливаются первыми: всё, что считает «сколько
прошло», видит уже защищённое время. `timers` и `dayRollover` в `Restore` только читают — события
об офлайн-истечении и смене суток публикуются на первой проверке после `RestoreAll`
(`SecondTick`, возврат из фона или снятие заморозки времени), а не из `Restore`, когда
подписчиков ещё может не быть. Нет секции — пустой список / текущие сутки без события.

## 2. Формат файла

Конверт с независимыми секциями:

```json
{
  "version": 1,
  "savedAtUtc": "2026-09-14T10:20:30Z",
  "sections": {
    "wallet": { "balances": { "soft": 1200, "hard": 40 } },
    "level":  { "campaign": 17 }
  }
}
```

**Битая или незнакомая секция не ломает весь сейв** — её участник получает дефолт. Миграции
тоже посекционные.

Сериализатор — **Newtonsoft.Json** (`com.unity.nuget.newtonsoft-json`). `JsonUtility` не годится:
не умеет словари, пришлось бы плодить плоские DTO-массивы и конвертировать руками.

## 3. Политика записи

```csharp
public enum SaveReason
{
    Routine,    // мелочь: настройки, косметика
    Important,  // уровень пройден, баланс изменился, покупка за игровую валюту
    Critical,   // покупка за реальные деньги, завершение туториала
}
```

| Триггер | Локально | Облако |
|---|---|---|
| `MarkDirty(Routine)` | троттлинг, не чаще 1 раза в N секунд | нет |
| `MarkDirty(Important)` | сразу | нет |
| `MarkDirty(Critical)` | сразу | сразу |
| `OnApplicationPause(true)` | сразу | да |
| `OnApplicationFocus(false)` / Quit | сразу | да |

Облако трогается: один раз при загрузке, при сворачивании и на Critical. Всё.

## 4. Ловушки, без которых это ломается на проде

- **`OnApplicationQuit` на Android не гарантирован** — система сносит процесс без вызова.
  Надёжный хук — `OnApplicationPause(true)`; `OnApplicationQuit` только дубль. Слушает их
  `ApplicationLifecycleWatcher` на `ServicesRoot`.
- **Атомарная запись.** Писать в `save.tmp`, затем `File.Replace` на `save.json` с сохранением
  `save.bak`. Иначе убитое во время записи приложение оставляет обрезанный файл — потерянный
  аккаунт игрока.
- **Снапшот синхронно, запись асинхронно.** `Capture()` всех участников — в главном потоке
  (быстро). Сериализация и запись — `UniTask.RunOnThreadPool`. Фризов нет, участники не меняются
  во время записи. **Кроме WebGL:** там потоков нет, `SwitchToThreadPool`/`RunOnThreadPool` вешают
  `await` навсегда — загрузка сейва на старте не вернётся. Под `UNITY_WEBGL && !UNITY_EDITOR`
  I/O на главном потоке, шаблон `LocalFileSaveStorage` это уже делает.
- **Коалесинг.** Несколько `MarkDirty` в одном кадре схлопываются в одну запись, иначе смерть
  врага (валюта + опыт + уровень) даёт три записи подряд.
- **Конфликт при загрузке.** Облачный сейв свежее локального по `savedAtUtc` и прогрессу —
  показать игроку выбор, а не молча затереть. Для idle обязательно: переустановка, второе
  устройство.
- **Ни одной записи до `RestoreAll`.** Сервисы инициализируются раньше `LoadSaveOperation`;
  механика, которая на старте что-то начислила и позвала `MarkDirty`, иначе запишет пустой снимок
  поверх файла игрока. `SaveService` до конца `RestoreAll` игнорирует `MarkDirty` и
  `SaveNowAsync`, после — сбрасывает грязный флаг (восстановленное и так совпадает с файлом).
  Механике, публикующей события в `OnInitialize`, всё равно нужен свой флаг `_isRestored`
  (как в `DayRolloverService`), иначе события уйдут дважды — до и после загрузки.

### Запись: автосейв, а не надежда на лайфсайкл

`OnApplicationQuit` на Android — только при явном `Application.Quit`, а `OnApplicationPause`
иногда не успевает доработать до сворачивания. Поэтому запись держится на трёх ногах, лайфсайкл —
самая слабая:

- **Тик раз в секунду** проверяет грязный флаг и пишет, если с прошлой записи прошло
  `AUTOSAVE_INTERVAL_SECONDS`. Основной механизм.
- `MarkDirty(Important | Critical)` флашит следующим кадром.
- `MarkDirty(Routine)` **ничего не планирует** — его подбирает тик.

Раньше `Routine` при частых вызовах делал `return` без переотправки, и запись могла не случиться
вовсе. Не возвращай эту схему — у грязного флага обязан быть тот, кто его гарантированно разгребёт.

Принудительный флаш поверх интервала — `FlushIfDirty()`, пишет только если есть что писать:

- потеря фокуса (`IApplicationLifecycle.FocusChanged(false)`) — на десктопе и WebGL
  `OnApplicationPause` не приходит, фокус единственный сигнал;
- заморозка времени (`IPauseService.IsTimeFrozen` стал `true`) — `SecondTick` считает по
  `Time.deltaTime` и под паузой не идёт.

`OnApplicationPause(true)` по-прежнему пишет безусловно и с облаком; на Android за ним следует
`FocusChanged(false)`, но флаг уже сброшен, второй записи нет.

`_isDirty` сбрасывается **сразу после `CaptureAll`**, а не в конце записи: иначе изменение во
время асинхронной записи затиралось бы её финалом. При ошибке записи флаг ставится обратно.

Повторный `SaveNowAsync` во время идущей записи не выбрасывается, а ставит `_hasPendingWrite` и
переотправляется в `finally`.

### Версия и миграции

`SaveEnvelope.Version` проверяется при загрузке. Миграции — реализации `ISaveMigration` с
`FromVersion`, резолвятся лениво и применяются по цепочке, пока версия не догонит
`CURRENT_VERSION`. Версию поднимает не миграция, а `SaveService` (`FromVersion + 1`) —
бесконечный цикл структурно невозможен.

Сейв из **более новой** версии не затирается и не выбрасывается: громкая ошибка и попытка
прочитать как есть. Отсутствие нужной миграции — тоже громкая ошибка.

### Конфликт с облаком решается счётчиком, а не временем

В конверте `saveCounter`, растущий на каждой записи. `ResolveConflict` сравнивает сначала его,
при равенстве — `savedAtUtc` из `IGameClock`. По одному времени игрок с переведёнными вперёд
часами всегда выигрывал бы у облака.

Граница: счётчик не решает настоящий конфликт двух устройств — у обоих снимков может быть
одинаковый счётчик. Play Games отдаёт игре оба снимка и ждёт слияния или выбора игрока; у нас
этого нет.

### Шифрование включается типом билда

`ISaveCodec` применяется в `SaveService` вокруг сериализации — одинаково для локального
хранилища и облака. `SaveCodec` принимает флаг в конструкторе, `CoreInstaller` выбирает его под
`#if UNITY_EDITOR || DEVELOPMENT_BUILD`: в редакторе и дев-билде — открытый JSON, в релизе — AES.

**Чтение всегда понимает оба формата.** Payload, начинающийся с `{`, — открытый JSON; остальное
пробуется расшифровать. Иначе релиз не прочитал бы сейвы дев-билда, а откат терял бы релизные.

Ключ выводится из `Application.identifier` плюс константа-соль, литерального секрета в репозитории
нет. **Это обфускация, а не защита:** ключ едет в клиенте и извлекается за десять минут. Задача —
закрыть правку сейва блокнотом. Для игр с реальными деньгами нужен сервер.

### Участники резолвятся лениво — это не оптимизация

`SaveService` держит участников как `LazyInject<List<ISaveParticipant>>` и разворачивает список
при первом обращении, а не в конструкторе.

Почти каждый участник инжектит `ISaveService` (ради `MarkDirty`). Если `SaveService` просит
`List<ISaveParticipant>` в конструкторе, Zenject строит всех участников, а каждому нужен сейв-сервис —
конструкторный цикл, игра не стартует.

Лениво резолвится именно **список**: к первому `RestoreAll` или `CaptureAll` все
`NonLazy`-участники уже построены, список приходит полным.

**Не возвращай `List<ISaveParticipant>` в конструктор.** Симптом — `ZenjectException:
Circular dependency detected` при старте. Чинить в каждой механике через `LazyInject<ISaveService>`
бессмысленно: лечение симптома, лишний слой в каждом сервисе и ловушка для следующего, кто напишет
механику по образцу библиотеки.

## 5. Загрузка

Шаги `LoadSaveOperation` и `RestoreProgressOperation` в конвейере Boot, **до** загрузки игровой
сцены. К старту геймплея все участники восстановлены.

Нет файла — `SaveEnvelope.CreateDefault()`, каждый участник получает `null` и инициализируется
дефолтами. Штатный путь новой установки, не ошибка.

## 5a. Сброс сейва в редакторе

`Editor/SaveTools.cs` — меню `Tools → Clear Save`, заводится вместе с фундаментом. Удаляет папку
`LocalFileSaveStorage.DirectoryPath` целиком (`save.json`, `.tmp`, `.bak`) и `PlayerPrefs`. Путь
берётся из хранилища, строкой не дублируется.

В Play Mode сначала останавливает игру и удаляет только после `EnteredEditMode`: на выходе сейв
пишется по `Quitting`, и удалённый раньше файл тут же вернулся бы.

Если появится рантайм-вайп (`ISaveService.WipeAsync` — сброс живого состояния участников и
перезагрузка игровой сцены), в Play Mode меню переключают на него: игрок начинает сначала, не
выходя из Play Mode. Облако сброс в редакторе не трогает — там заглушка площадки.

## 6. Облако

`CloudSaveStorage` реализует тот же `ISaveStorage` и подключается через `IPlatformSdk`. Площадка
без облака — `Supports(PlatformCapability.CloudSave) == false`, остаётся локальное хранилище.
Игровой код разницы не видит.
