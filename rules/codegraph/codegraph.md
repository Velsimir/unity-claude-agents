# Правило: искать код через CodeGraph

Граф находит символы и вызовы через интерфейсы за один заход вместо цепочки Grep → Read.
Факты (команды, конфиг под Unity, границы): `~/.claude/Database/codegraph/CODEGRAPH.md`.

## Порядок в проекте

1. Нет `.codegraph/` в корне — Grep/Glob. Не индексировать молча (`init` — минуты и сотни МБ),
   можно предложить одной строкой.
2. Есть — первый поиск через `codegraph explore "<вопрос или имена символов>"`.
3. Ответ расходится с файлом — `codegraph sync` и повтор → `codegraph index` → Grep и сказать
   владельцу, что граф протух.

## Когда синхронизировать

Авто-синк работает сам. Руками `codegraph sync` — после массового создания/переименования/удаления
файлов, `git pull`, смены ветки, при pending в `codegraph status`. После правки тела метода — не
нужно.

## Новый проект

Заводится вместе с project-level `CLAUDE.md` — порядок в
`~/.claude/rules/project-claude-md/project-claude-md.md`, раздел «Вместе с CLAUDE.md —
граф кода». `init` до `codegraph.json` затянет `Library/PackageCache`.

## Чего граф не видит

Сцены, префабы, связи из инспектора, значения SO, загрузку по строковым путям — там Unity MCP, Read,
Grep. Пустой `impact` не доказывает неиспользуемость: перед удалением — контрольный Grep по имени.

## После обновления плагина

`codegraph upgrade` может вписать маркерный блок в `~/.claude/CLAUDE.md` — проверить конец файла и
удалить (указатель на это правило там уже есть).
